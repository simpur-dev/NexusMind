# 事件工作台分阶段回测方案

## 测试思路

选取一个已完结的真实高校舆情事件，按时间线拆成 4 个阶段。
每个阶段只向系统提供"截至当时"的已知信息，观察系统是否能：

1. **流程层面**：正确执行 材料追加 → 基线重建 → 预测分支 → 决策简报
2. **准确度层面**：系统预测的风险/走势/推荐动作是否与后续真实发展吻合

## 测试案例：华中农业大学 11 名研究生联名举报导师事件（2024年1月）

### 为什么选这个案例
- 时间线清晰，各阶段间隔明确
- 涉及学术不端、师生权力关系、学校治理等典型议题
- 舆论走势经历了完整的 爆发→发酵→回应→处置→消退 周期
- 最终结果已公开，可做准确度对照

## 四个阶段

| 阶段 | 时间 | 喂入内容 | 验证重点 |
|------|------|---------|---------|
| Phase 1 | D0 爆发期 | 举报信原文 + 初始社交媒体反应 | 系统能否识别核心风险？ |
| Phase 2 | D1-D3 发酵期 | 媒体跟进 + 学校初步回应 | 系统预测走势是否合理？ |
| Phase 3 | D7 处置期 | 调查结果 + 处分公告 | 基线更新后预测是否调整？ |
| Phase 4 | D14-D30 消退期 | 后续影响 + 制度反思 | 系统是否正确判断事件进入消退？ |

## 运行方式

```bash
# 在 NexusMind 根目录下运行
python tests/incident_phased_test/run_phased_test.py
```

每个阶段会：
1. 追加该阶段材料
2. 重建基线（LLM 自动分析）
3. 对比基线变化
4. 输出基线摘要供人工判读
