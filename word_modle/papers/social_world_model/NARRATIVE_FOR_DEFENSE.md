# NexusMind 项目叙事与答辩指南

> 面向：计算机设计大赛评委  
> 更新日期：2026-05-05  
> 目的：用和当前项目一致的方式讲清楚 NexusMind 的定位、核心创新、已完成能力和验证证据。  
> 讲述原则：突出“早期种子材料 → 滚动预测 → 决策辅助”的应用价值，避免把系统说成纯盲测或绝对预测系统。

---

## 一、30 秒电梯演讲

> **NexusMind 是一个面向公共事件的舆情推演与决策辅助系统。**
> 它不是只把材料做摘要，也不是简单让一批 Agent 发帖，而是把用户提交的现实种子材料转化为一个可追踪、可推演、可复核的数字社会沙盘。
>
> 系统会从材料中抽取事实、主体和关系，构建事件记忆图谱；再基于图谱生成多类 Agent 画像和推演参数，让 Agent 在信息广场和话题社区中交互；同时用社会世界模型持续追踪关注度、情绪压力、公众信任、立场极化、综合风险和系统稳定性六个状态变量。
>
> 这样，系统最终输出的不只是“大家说了什么”，而是“事态可能怎么走、风险在哪一轮升高、哪些主体和事件推动了变化、下一步处置应该关注什么”。随着现实事件继续发展，用户还能追加新材料、重建事实基线、创建新的预测分支，形成滚动研判闭环。

---

## 二、当前项目一句话定位

**NexusMind = 事件记忆图谱 × 多智能体社会推演 × 六维社会世界模型 × 可复核 Benchmark 的滚动决策辅助系统。**

更具体地说，它解决的是：

- **输入从哪里来**：现实种子材料、文件上传、手动文本和网络抓取。
- **事实怎么组织**：Graphiti + Neo4j 构建事件记忆图谱，形成事实基线。
- **未来怎么预演**：OASIS / CAMEL 多智能体在双平台环境中模拟传播与互动。
- **局势怎么衡量**：WorldStateEngine 维护六维社会状态，CausalGraphEngine 追踪事件因果链。
- **结果怎么解释**：ReportAgent 通过 ReACT 工具链调用图谱、世界模型、因果链、评估和证据检索工具生成报告。
- **效果怎么验证**：Benchmark 用 TCS、TPH、KAC、EOA 四项指标对照真实案例。

## 三、系统真实工作流

```text
现实种子材料
   │
   ▼
材料解析 / 网络抓取 / 分阶段追加
   │
   ▼
事实基线 Baseline Snapshot
   │
   ▼
事件记忆图谱 Graphiti + Neo4j + GraphRAG / VectorRAG
   │
   ▼
群体环境建模：Agent 画像、认知先验、平台参数、模拟配置
   │
   ▼
OASIS / CAMEL 双平台推演：信息广场 + 话题社区
   │
   ▼
社会世界模型：六维状态、事件流、因果链、现实校准
   │
   ▼
决策简报 / 智能追问 / Benchmark 评估 / 分支对比
```

对应前端五步：

| 步骤 | 页面含义 | 答辩时说法 |
|---|---|---|
| Step 01 事件图谱生成 | 从材料抽取主体、关系和事件线索 | “先把现实锚点固定下来，避免凭空推演” |
| Step 02 群体环境建模 | 生成 Agent 画像、认知先验和模拟参数 | “把事件中的关键主体转化为可交互的群体角色” |
| Step 03 舆情态势推演 | 双平台交互，世界模型实时记录状态 | “这里是系统核心：个体行为推动社会状态变化” |
| Step 04 决策简报生成 | ReportAgent 生成结构化研判报告 | “报告不是纯生成，而是调用图谱、状态、因果链和评估证据” |
| Step 05 智能追问研判 | 对报告和 Agent 结果继续追问 | “支持答辩和实际应用中的二次解释” |

## 四、世界模型到底解决了什么

传统多 Agent 模拟容易停留在“许多角色在互动”。NexusMind 加入社会世界模型后，系统开始显式维护“局势本身”的变化。

### 4.1 六维宏观状态

| 状态变量 | 中文含义 | 答辩解释 |
|---|---|---|
| `attention_level` | 舆论关注度 | 事件热度、讨论规模和传播强度 |
| `panic_level` | 情绪压力 | 负面情绪、焦虑和恐慌扩散程度 |
| `trust_level` | 公众信任 | 群体对组织、权威或官方回应的信任 |
| `polarization_level` | 立场极化 | 群体分歧、对立和叙事撕裂程度 |
| `risk_level` | 综合风险 | 事件升级、次生风险和治理压力 |
| `stability_level` | 系统稳定性 | 舆论环境是否趋于收敛和平稳 |

### 4.2 当前已落地的闭环

```text
Agent 行为日志
   │
   ▼
WorldStateEngine
   ├─ 规则 + LLM 辅助更新六维状态
   ├─ 话题状态追踪 TopicState
   ├─ 阶段先验与现实校准
   └─ 事件检测：瞬时跳变 + 滑动窗口趋势
   │
   ▼
CausalGraphEngine
   ├─ triggered / amplified / suppressed / correlated
   └─ 状态变化验证 + 可选 LLM 推断
   │
   ▼
SimulationInsightService / ReportAgent
   ├─ 世界模型简报
   ├─ 状态演化分析
   ├─ 因果链分析
   ├─ 态势评分卡
   ├─ 决策支持简报
   └─ 模拟证据检索
```

### 4.3 和普通摘要系统的区别

| 维度 | 普通舆情分析 | NexusMind |
|---|---|---|
| 分析对象 | 已发生文本 | 事件未来演化轨迹 |
| 数据组织 | 文档摘要、关键词、情感 | 事实基线、事件图谱、Agent 群体、世界状态 |
| 推演方式 | 事后统计 | 多智能体交互 + 世界状态反馈 |
| 可解释性 | 给结论但证据链弱 | 状态曲线、事件流、因果链、Agent 行为日志 |
| 使用方式 | 一次性报告 | 追加材料、重建基线、分支预测、滚动研判 |

## 五、当前最重要的创新点

### 5.1 从“材料分析”到“数字社会沙盘”

系统不是只读取材料，而是把材料转化为：

- 事件图谱中的事实节点和关系边
- Agent 的身份、立场、目标和认知先验
- 推演平台中的初始话题和交互环境
- 世界模型中的初始状态和阶段先验

这让后续推演有现实锚点，而不是凭空生成。

### 5.2 从“单次报告”到“滚动研判闭环”

真实事件不是一次性结束的。NexusMind 支持：

- 早期只输入当前已知材料
- 随着新通报、新媒体报道、新舆论反馈出现，继续追加材料
- 重建 Baseline Snapshot
- 创建校准后的预测分支
- 对比不同处置方案和不同阶段结果

这和项目应用目标高度一致：**在事件发生的第一时间给出参考，然后随着现实信息更新持续修正判断。**

### 5.3 从“黑箱生成”到“可复核证据”

系统会保留：

- `world_state_history.jsonl`
- `events.jsonl`
- `causal_edges.jsonl`
- `twitter/actions.jsonl`
- `reddit/actions.jsonl`
- `simulation_config.json`
- `full_report.md`
- `evaluation_result.json`
- `benchmark_score.json`

所以报告中的判断可以回到状态、事件、行为和评分文件中复核。

## 六、验证证据怎么讲

答辩时建议优先使用 **真实案例 Benchmark**，它比“内部 A/B 盲评胜率”更容易解释、更稳。

### 6.1 Benchmark 指标

| 指标 | 含义 | 权重 |
|---|---|---:|
| TCS | 趋势一致性：模拟阶段走势是否与现实一致 | 35% |
| TPH | 转折点命中率：是否命中现实关键拐点 | 25% |
| KAC | 关键主体覆盖：图谱、Agent、报告是否覆盖关键主体 | 20% |
| EOA | 事件顺序准确性：事件链顺序是否与现实一致 | 20% |

### 6.2 已有案例结果

| 案例 | 结果 | 可展示价值 |
|---|---:|---|
| Case 01 武汉大学图书馆争议 | `benchmark_score_sim656a_v5.json`：99.3 / A | 展示复杂争议事件中的趋势、二次争议和主体覆盖 |
| Case 02 华中农业大学学术不端举报 | `benchmark_score.json`：100.0 / A | 展示阶段趋势、关键转折点、主体覆盖和事件顺序完整命中 |

推荐说法：

> Benchmark 不是为了宣称系统可以绝对预测未来，而是验证系统能否在给定材料与事实边界内，复现真实案例中的阶段趋势、关键拐点、关键主体和事件顺序。我们把可验证部分落到了评分脚本和 JSON 结果里，避免只凭主观演示。

### 6.3 内部 A/B 验证怎么处理

项目中保留了 `backend/tests/llm_validation_large.py` 和 `llm_validation_large_result.json`，可作为研发阶段对世界模型效果的参考。当前答辩建议只把它作为“内部消融测试”补充说明，不作为主证据。

主证据优先级：

1. 真实案例 Benchmark 分数
2. 模拟产物文件和报告
3. 前端五步流程截图或视频
4. 内部 A/B 验证脚本

## 八、评委可能追问的问题

### Q1：你们是不是只是在调用大模型写报告？

不是。大模型主要用于文本理解、图谱构建辅助、Agent 画像生成和 ReportAgent 推理。系统的核心过程还包括图谱存储、模拟运行、世界状态更新、事件检测、因果链推断、JSONL 轨迹记录和 Benchmark 评分。报告是最后的表达层，不是全部能力。

### Q2：为什么需要世界模型？

如果没有世界模型，多 Agent 模拟只能看到“谁发了什么”。世界模型把这些个体行为聚合成关注度、信任、情绪压力、极化、风险和稳定性等宏观变量，让系统能够解释“局势为什么升温、什么时候转折、哪些因素导致风险变化”。

### Q3：你们能保证预测真实未来吗？

不能也不应该这样承诺。NexusMind 的定位是决策辅助和情景推演：在给定材料边界和模型假设下，提前呈现可能的传播路径、风险拐点和干预窗口。真实世界会受到更多外部变量影响，所以系统支持后续追加材料和滚动校准。

### Q4：Benchmark 分数代表什么？

代表系统输出与真实案例参考链在四个可验证维度上的一致性：趋势、转折点、主体和事件顺序。它不是对未来全知全能的证明，而是对“系统是否抓住真实演化主线”的量化验证。

### Q5：和传统舆情监测工具相比强在哪里？

传统工具偏事后监测，告诉你已经发生了什么；NexusMind 更强调事前和事中推演，回答“如果当前信息继续发酵，可能出现哪些风险”“如果现在补充回应，可能改变哪些轨迹”。

### Q6：当前系统还有什么边界？

当前系统已经跑通材料接入、图谱构建、Agent 建模、世界状态闭环、报告生成和 Benchmark 验证。但它仍依赖输入材料质量、LLM 可用性、模拟轮次设置和案例标注质量。后续会重点加强多案例验证、准实时案例验证、前端评估展示和分支对比可视化。
